# Yêu cầu hệ thống SMS (bản chuẩn để code)

> Nguồn: mục 2.3.2 tab "Bài làm chính", Google Doc *OULINE - KTHT Sáng 4 - Quy trình Sales*, bản đọc ngày **22/10/2026** (100 FR, 15 NFR).
> File này là **bản sao để code**. Nội dung FR giữ nguyên câu chữ của nhóm, kể cả lỗi chữ; các cột Module, WP, Cổng, BR, Hiện trạng do người lập kế hoạch thêm vào.
> Khi nhóm sửa doc, cập nhật lại file này trước rồi mới code. Không tự sửa câu chữ FR trong file này để "cho dễ code".
> **Mã FR đã đổi so với bản 19/10.** Bảng đổi mã ở cuối file. Mọi tài liệu trong repo đã dùng mã mới.

## Cách đọc

- **Module**: module cấp 1 ở mục 2.3.1 của bài (7 module, 69 chức năng cấp 3).
- **WP**: gói việc chịu trách nhiệm cài FR đó, xem `docs/WORKPLAN.md`. Sáu FR có Agent nằm trong bảng nghiệp vụ (FR-06, FR-19, FR-20, FR-32, FR-36, FR-44) vẫn thuộc **WP-08**.
- **Cổng**: điểm kiểm soát của con người (HG1–HG8) hoặc điểm duyệt khác. Mỗi cổng phải có test riêng, xem mục *Cổng kiểm soát* bên dưới.
- **BR**: quy tắc nghiệp vụ có giá trị cụ thể trong `docs/requirements/BUSINESS-RULES.md`. Mọi chỗ FR ghi "theo quy tắc được xác nhận / cấu hình" thì dùng BR tương ứng.
- **Hiện trạng**: ước lượng mức code hiện có (Có / Một phần / Chưa) tại ngày 19/10/2026. WP-00 kiểm lại và cập nhật.
- **Nguồn yêu cầu** hoặc mô tả có chữ "chưa chốt", "cần chốt": dùng giá trị mặc định trong `docs/requirements/DECISIONS.md`, không tự đặt quy tắc khác.
- **Dữ liệu**: thực thể và bảng tương ứng xem `docs/requirements/DATA-MODEL.md` (theo ERD mục 2.4.3).
- Mỗi FR khi cài xong phải có ít nhất một test có tên bắt đầu bằng mã FR, ví dụ `it("FR-33: chuyển đổi dùng lại Account đã có")`.
